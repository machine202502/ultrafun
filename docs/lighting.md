# Как устроен свет

## Коротко

Свет в игре складывается из:

1. **Подсветки** (ambient) — слабый свет везде, чтобы тени не были чёрными. Сверху у неё один цвет, снизу другой (например, сверху прохладный, снизу тёплый): так объёмы лучше читаются.
2. **«Солнца»** — свет одного направления сверху. В помещениях «Утилизации» почти выключено.
3. **Ламп** — точечных источников: те, что стоят в уровне, и временные вспышки.
4. **Отражённого света** — свет ламп, отскочивший от стен, пола и потолка. Он заранее «запекается» при загрузке уровня: поэтому тени не чёрные, а пол рядом с красным ящиком чуть краснеет.

Лампы уровня **отбрасывают тени**: свет не проходит сквозь стены. На месте каждой лампы виден **светящийся плафон** её цвета.

Кроме света, стиль задаёт **вид поверхностей**: пиксельные панели, которые шейдер рисует на всех стенах, разную яркость граней (верх светлее, бока темнее) и насыщенность цвета. Основной режим `arcade` сделан под картинку ULTRAKILL: светло, насыщенно, тени слабые, реалистичный свет не главное.

Весь внешний вид света задаётся **стилем освещения**, и его можно крутить прямо в игре — в панели **F3**.

## Панель F3 — лаборатория света

Нажмите **F3** — откроется окно с настройками. Мышь освобождается, можно двигать ползунки; игра продолжает рисоваться, всё меняется сразу.

**Режимы** (выпадающий список `preset`):

| Режим | Как выглядит |
|---|---|
| `arcade` | Под ULTRAKILL: светло, пиксельные панели на всех поверхностях, грани разной яркости, насыщенные цвета, без тонмаппинга, слабые тени. **Выбран сейчас** |
| `retro_flat` | Старый вариант: без теней, ступенчатый «пиксельный» свет, упрощённая яркость. Для сравнения |
| `shadows` | Тени, мягкие края, правильная яркость, плавный свет, отражённый свет |
| `retro_shadows` | Тени крупными пикселями, ступени яркости |
| `grim_factory` | Тени, тёмная подсветка, густой туман, яркие плафоны |

**Ползунки и галочки:**

| Параметр | Что делает |
|---|---|
| `linear light + tone mapping` | Правильный расчёт яркости. Выключить — получится старый «плоский» расчёт |
| `exposure` | Общая экспозиция — как выдержка у фотоаппарата: больше — светлее всё сразу |
| `lamp brightness` | Яркость всех ламп |
| `ambient` | Сила подсветки в тени |
| цвета `ambient from above / from below` | Цвет подсветки сверху и снизу |
| `pixel texture` | Сила пиксельной «текстуры» панелей, которая рисуется прямо в шейдере. `0` — гладкий цвет |
| `texture pixels per meter` | Размер пикселя текстуры: 8 — пиксель 12,5 см, панель 2 м |
| `face shading` | Грани разной яркости по направлению: верх светлый, бока темнее, низ тёмный. Форма читается без реалистичного света |
| `saturation` | Насыщенность цвета: 1 — как есть, больше — ярче |
| `light texel` | Размер «квадратика» ступенчатого света в метрах. `0` — плавный свет |
| `light bands` | Число ступеней яркости. `0` — без ступеней |
| `shadows` | Включить тени |
| `shadow resolution` | Чёткость теней: 32–64 — крупные пиксели, 256 — чёткие |
| `soft edges` | Смягчить края теней |
| `shadow strength` | Насколько темна тень: 1 — полностью, 0 — тени нет |
| `bounced light` | Включить отражённый свет |
| `bounce strength` | Его сила. При включённом отражённом свете `ambient` стоит держать низким, иначе ровная подсветка его заглушит |
| `bake texel, m` | Размер квадрата запекания: меньше — точнее, но дольше запекается |
| `bounces` | Сколько раз свет отскакивает: 1 — только ближние отсветы, 2–3 — свет доходит до дальних углов |
| `fog distance` | Дальность тумана: меньше — туман гуще |
| `visible lamp fixtures`, `fixture size` | Показывать плафоны ламп и их размер |

**Кнопки:**
- **save into preset** — записать текущие значения в выбранный режим в файле `assets/data/lighting.ron` и сделать его режимом по умолчанию;
- **reset** — вернуть значения выбранного режима из файла.

Хотите свой вариант, не трогая готовые, — скопируйте любой режим в `lighting.ron` под новым именем (`name`), он появится в списке.

## Тени

Тени есть только у **ламп уровня** (до 24 штук). Вспышки выстрела и смерти, свечение деталей — без теней (они короткие и маленькие).
Узкие тёмные клинья на потолке зала, расходящиеся от верха колонн, — это тени колонн: лампы висят на 4,5 м ниже потолка, и свет на потолок падает почти вскользь. Не ошибка.

Враги и двери **теней не отбрасывают** — тени считаются только от стен и полов уровня. Сделано ради скорости; можно добавить позже.

## Отражённый свет

Считается один раз при загрузке уровня (около полутора секунд) и заново — если поменять `bounced light`, `bake texel` или `bounces`. Остальные ползунки, включая `bounce strength`, меняют картинку сразу.

Отражённый свет есть только у стен и полов уровня. Враги и двери его не получают — их освещают лампы и подсветка. Вспышки выстрелов не отражаются.

## Режим скриншотов

```
cargo run --release -- --screenshots
```

Игра снимает каждый режим освещения с нескольких точек уровня и закрывается. Снимки — в `target/screenshots`, имена вида `shadows__04_hall_entrance.png`. Точки камеры — в `tools/screenshots.ron`. Удобно, чтобы сравнить режимы рядом; агенты так проверяют свои правки света.

# Под капотом

## Как кадр попадает на экран

0. **Запекание (при загрузке уровня).** Считается атлас отражённого света — ниже, в «Отражённый свет».
1. **Тени (только когда нужно).** Если уровень сменился или поменялись настройки теней, для каждой лампы с тенью строится её карта теней (подробно ниже). В обычном кадре этот шаг пропускается.
2. **Сцена — в маленькую картинку** низкого разрешения (`internal_height`). Здесь считаются свет, тени, туман.
3. **Растягивание на окно** без сглаживания.
4. Поверх — интерфейс в полном разрешении: прицел, здоровье, субтитры, панели F1 и F3.

## Карты теней

Для лампы видеокарта «смотрит» из её точки в **шесть сторон** (±X, ±Y, ±Z — как грани куба), каждый раз с углом обзора 90°. Для каждого направления она рисует стены уровня и в каждом пикселе запоминает **расстояние от лампы до ближайшей стены**, делённое на дальность лампы. Получается 6 картинок на лампу; все они лежат в одном большом массиве (24 лампы × 6 = 144 слоя).

Лампы и стены неподвижны, поэтому карты строятся **один раз** — при загрузке уровня или при смене настроек теней (включить/выключить, разрешение). Дальше они просто используются.

**Проверка тени для точки стены:**
1. Точку чуть сдвигаем от поверхности по нормали (на размер одного пикселя карты на этом расстоянии) — иначе поверхность «затеняла бы сама себя» и покрывалась полосами.
2. Берём направление от лампы к точке и выбираем грань куба по самой большой составляющей (например, если направление больше всего по −Y — нижняя грань).
3. Проецируем точку на эту грань той же матрицей, что использовалась при построении, получаем пиксель карты.
4. Сравниваем: если расстояние до точки **меньше или равно** запомненному — точка освещена, иначе между ней и лампой есть стена.
5. С «мягкими краями» проверяются 9 соседних пикселей (3×3), и освещённость = доля освещённых. Края тени становятся плавнее.
6. `shadow strength` смешивает: `видимость = (1 − сила) + сила × освещённость`.

## Расчёт цвета пикселя

1. **Светится сам?** Плафоны ламп не освещаются, а светятся: их цвет усиливается в 4 раза и проходит через тонмаппинг — выглядят ярко, как источник света.
2. **Узор поверхности:** цвет материала умножается на пиксельную панель (ниже, «Пиксельная текстура и грани»).
3. **Перевод в линейные цвета** (если включён `linear light`): цвет материала, цвета подсветки и ламп возводятся в степень 2,2. Экранные цвета «сжаты» под глаз; складывать свет правильно можно только в линейных.
4. **Подсветка:** `смесь(цвет снизу, цвет сверху, (нормаль.y + 1) / 2) × базовая подсветка уровня × ambient`.
5. **Солнце:** `max(0, нормаль · направление к солнцу) × сила солнца`.
6. **Каждая лампа:** — `обращённость × край² / (d² + 1) × яркость`, плюс умножение на **видимость из карты теней**. Если включены квадратики света, точка для расчёта округляется до центра квадрата.
7. **Ступени** (если `light bands` > 0) округляют сумму солнца и ламп.
8. **Итог:** `цвет материала × (подсветка + солнце и лампы + отражённый свет) × яркость грани`. Отражённый свет берётся из атласа с плавной интерполяцией между квадратами и умножается на `bounce strength × lamp brightness`. Яркость грани — по `face shading`.
9. **Тонмаппинг** (если включён `linear light`): `цвет × exposure` прогоняется через кривую ACES — она мягко «сжимает» очень яркие значения в диапазон экрана, вместо того чтобы обрезать их в белое пятно. Затем перевод обратно в экранные цвета (степень 1/2,2).
10. **Насыщенность** (`saturation`).
11. **Туман** смешивает результат с цветом неба по расстоянию (дальность умножается на `fog distance`).
12. **Дизеринг и глубина цвета** — если включены в настройках картинки ([picture.md](picture.md#дизеринг-формула)).

## Пиксельная текстура и грани

Настоящих текстур пока нет, поэтому узор рисует шейдер по координатам точки в мире:

1. Берутся две координаты вдоль поверхности (для пола — X и Z, для стены — по её направлению) и умножаются на `texture pixels per meter`, затем округляются вниз — получается номер «пикселя текстуры».
2. Пиксели группируются в панели 16×16. Первый ряд панели — шов (яркость ×0,65), второй — светлая фаска (×1,12), последний — тень фаски (×0,85).
3. Каждый пиксель случайно светлее или темнее (×0,88…1,12), каждая панель целиком тоже (×0,9…1,1).
4. **Защита от мерцания (аналог анизотропной фильтрации).** Шейдер узнаёт, сколько пикселей узора попадает в один пиксель экрана, **отдельно по каждой оси** поверхности (по разнице координат с соседним пикселем экрана). Назовём это охватом по X и по Y. Стена сбоку сжата только по горизонтали, поэтому огрубляется только по горизонтали:
   - **шум:** по оси с охватом больше 1 соседние пиксели узора объединяются в блоки по 2, 4, 8… (ближайшая степень двойки не меньше охвата), и весь блок берёт одно случайное значение. Сила шума делится на √(площадь блока), как у среднего по блоку. Картинка остаётся пиксельной, блоки привязаны к стене;
   - **швы:** если охват больше 1, шов рисуется с силой «какую долю пикселя экрана он занимает»: число швов внутри охвата / охват. Вдали швы бледнеют, но не мерцают и не исчезают;
   - **фаски** видны полностью при охвате ≤ 1 и исчезают к охвату 2 по любой оси;
   - **разница яркости панелей** исчезает, когда охват больше 16–32 (панель меньше пикселя экрана).

   Без этого вдали и под острым углом каждый кадр брался случайный пиксель узора, и при движении текстура мерцала и «ползла». Первая версия огрубляла по самой сжатой оси обе оси сразу, и стены сбоку размывались в мыло.
5. Результат умножает цвет материала, `pixel texture` смешивает его с гладким цветом.

**Узор и дрожание вершин несовместимы.** При `vertex_snap: true` (`settings_default.ron`) каждая вершина округляется до пикселя экрана. Стены и пол — огромные треугольники, и дальняя вершина при округлении сдвигается в мире на сантиметры, а узор считается по исходным координатам. В итоге при каждом движении камеры узор съезжает внутри треугольника на долю своего пикселя. Поэтому дрожание вершин по умолчанию выключено.

**Грани:** `яркость = n.y² × (1 сверху или 0,5 снизу) + n.x² × 0,8 + n.z² × 0,65`, где n — нормаль; `face shading` смешивает её с 1. Применяется к итоговому свету.

**Насыщенность:** итоговый цвет смешивается с его яркостью `0,299 R + 0,587 G + 0,114 B`: `серый + (цвет − серый) × saturation`.

## Отражённый свет: как запекается

Уровень состоит только из боксов, поэтому считать можно прямо на процессоре, без сторонних программ.

1. **Атлас.** Каждая грань каждого бокса делится на квадраты (тексели) со стороной `bake texel` метров, но не больше 128 на сторону. Все грани раскладываются рядами в одну картинку шириной 2048 пикселей, вокруг каждой — рамка в 1 пиксель, повторяющая край (чтобы при интерполяции не подмешивался соседний кусок). Каждая вершина уровня получает координаты своего места в атласе.
2. **Прямой свет.** Для центра каждого текселя (сдвинутого на 2 см от поверхности) и каждой лампы: если лампа в пределах дальности и смотрит на поверхность, пускаем луч к лампе. Ничего не задело — добавляем свет по той же формуле, что и в реальном времени: `цвет × яркость × обращённость × край² / (d² + 1)`. Цвета переводятся в линейные (степень 2,2).
3. **Отскоки.** Повторяем `bounces` раз: из каждого текселя пускаем 64 луча в полусферу над поверхностью — чаще ближе к перпендикуляру (косинусное распределение, так свет собирается правильно без лишних умножений). Для каждого попадания берём тексель, куда попал луч: `(его прямой свет + его отражённый с прошлого отскока) × цвет той поверхности`. Среднее по 64 лучам — новый отражённый свет текселя. Набор направлений у соседних текселей повёрнут случайно, чтобы не было узора.
4. **Если точка внутри другого бокса** (например, кусок пола под стеной), луч сразу считается заблокированным — свет туда не протекает.
5. Атлас хранит только отражённый свет (16-битные числа с плавающей точкой). Прямой свет на экране по-прежнему считается в реальном времени с картами теней — он чётче и освещает врагов.
6. Работает во всех потоках процессора: ~1,4 с на «Утилизацию» при `bake texel` 0,5 м и 2 отскоках (release-сборка).

## Почему было некрасиво и что исправлено

| Было | Стало |
|---|---|
| Свет проходил сквозь стены | Карты теней |
| Свет складывался в экранных цветах и упирался в белый — грязные пятна | Линейный расчёт + тонмаппинг |
| Подсветка в тени — один серый цвет | Два цвета: сверху и снизу |
| Свет из пустоты | Видимые плафоны |
| Тени чёрные или залиты одним цветом, поверхности не влияют друг на друга | Запечённый отражённый свет |
