# Стек

**Язык:** Rust (edition 2024, stable toolchain; проверено на rustc 1.98.1).
**Движок:** нет. Свой минимальный движок поверх библиотек, только под нужды этой игры.
**Скриптовый язык:** нет. Вся логика на Rust, настраиваемые числа в файлах данных.

## Платформы

| Платформа | Графический API (через wgpu) | Примечание |
|---|---|---|
| Windows 10/11 | DX12 или Vulkan | |
| Linux | Vulkan | Нативная сборка, не через Proton |
| Steam Machine / Steam Deck | Vulkan | SteamOS — это Linux, работает та же сборка. Для них обязателен геймпад (см. «Подключаем позже») |

macOS и консоли не поддерживаем.

## Настройки и сохранения

- Пути — через `directories::ProjectDirs` (на Windows `%APPDATA%`, на Linux `~/.config` и `~/.local/share`).
- `<config>/settings.ron` — настройки: графика, звук, управление, чувствительность.
- `<data>/saves/progress.ron` — прогресс.
- Формат RON через `serde`. Запись через временный файл и переименование, чтобы не повредить файл при падении.
- Нет файла или он битый — используются значения по умолчанию, ошибка пишется в лог.

## Профилирование

- **Tracy**: внешнее приложение-профилировщик, игра отправляет в него данные через `tracy-client`.
- Подключается только cargo-фичей `profile`. В обычной сборке профилировщика нет совсем.
- Версия приложения Tracy должна совпадать с версией протокола `tracy-client` (таблица соответствия — в README `tracy-client`).
- `puffin` отвергнут: `puffin_egui` отстаёт по версии от нашего `egui`.

## Физика

Два независимых уровня. Они не смешиваются.

### Геймплейная: свой код + `parry3d`
Всё, что влияет на игру: движение игрока и врагов, снаряды, попадания, зоны урона.
- Игрок и враги — не физические тела, а позиция и скорость, которые двигает наш код.
- `parry3d` только отвечает на вопросы: луч, протаскивание формы вдоль пути, пересечения.
- Логика обновляется с фиксированным шагом (120 Гц), отрисовка сглаживает положение между шагами.
- Игрок и снаряды проверяются вдоль всего пути движения, а не только в конечной точке.

### Косметическая: `rapier3d`
Спецэффекты: разлёт обломков коробки, куски врагов, гильзы, падающий мусор.
- Отдельный физический мир, который ничего не знает о геймплее.
- Тела сталкиваются только со статической геометрией уровня и между собой. Игрока, врагов и снаряды не толкают и не блокируют.
- Ничего геймплейного не зависит от косметических тел. Мир можно выключить, и игра пройдётся так же.
- Лимит одновременных тел и время жизни у каждого. При превышении старые удаляются.
- Мелкие частицы (искры, капли крови) — простое движение с гравитацией в нашем коде, без `rapier3d`.

## Совместимость

- `egui-wgpu` 0.37 требует `wgpu` 30 и `winit` 0.30.13. Эти три пакета обновляются только вместе.
- `glam` у нас той же версии, что у `parry3d` 0.31 (0.33): типы коллизий и игры совпадают, конвертация не нужна. `glam` обновляется только вместе с `parry3d`.
- `kira` использует `glam` 0.34 — на границе со звуком позиции передаются через компоненты `x, y, z`.
- Последние `winit` 0.31 и `notify` 9 — бета-версии. Не использовать до стабильного релиза.

## Подключаем позже, только при реальной нужде

| Пакет | Когда |
|---|---|
| `rapier3d` 0.36.1 | Первый косметический физический эффект (см. раздел «Физика») |
| `rand` | Случайность понадобится вне геймплея: генерация ассетов, звуков, dev-инструменты. В игровом процессе игрок со случайностью не сталкивается ([decisions.md](decisions.md)) |
| `gilrs` 0.11.2 | Поддержка геймпада. Не позже подготовки к Steam Machine / Steam Deck. Ввод уже идёт через действия ([architecture.md](architecture.md#ввод)), поэтому геймпад добавляется только в `input/` |
| `mlua` или `rhai` | Компиляция станет реальным тормозом, а данных в RON не хватит |

## Сознательно не используем

- **Bevy, Fyrox** и другие движки — противоречат идее своего движка; API Bevy часто ломается, агенты знают старые версии.
- **ECS-библиотеки** (`hecs`, `bevy_ecs`) — для арены с десятками врагов достаточно `Vec` обычных структур.
- **Готовые контроллеры персонажа** — управление пишем сами, это сердце игры.
- **async-рантаймы** (`tokio` и т.п.) — игре не нужны.
