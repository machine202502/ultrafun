# specs/

Документы для агентов. Здесь описано, **как** мы пишем код и **что** должно быть сделано.

## Структура

```
specs/
├── README.md        — этот файл
├── stack.md         — язык, платформы, пакеты, версии
├── architecture.md  — устройство кода
├── assets.md        — ассеты: лицензии, источники, форматы
├── principles.md    — инженерные принципы (почему так)
├── code-style.md    — правила кода (как именно)
├── testing.md       — правила тестов
├── workflow.md      — порядок работы над задачей
├── decisions.md     — журнал решений
└── features/
    ├── _template.md — шаблон спека фичи
    └── <фича>.md    — спеки фич
```

## Правила для самих спеков

- **Коротко.** Спек длиннее одного экрана — повод его разрезать или выкинуть лишнее.
- **Конкретно.** «Игрок делает рывок на 5 метров за 0.15 с» вместо «рывок должен ощущаться хорошо».
- **Без реализации.** Спек описывает что и зачем. Как — решает агент по принципам проекта.
- **Актуально.** Поменялось поведение — поменяй спек в той же задаче. Устаревший спек хуже отсутствующего.
- **Один источник истины.** Правило записано в одном месте, остальные ссылаются.

## Приоритет при конфликте

1. Прямое указание человека в задаче.
2. Спек фичи.
3. `decisions.md`.
4. `principles.md`, `code-style.md`, `testing.md`.
5. Существующий код.

Если нашёл противоречие — не выбирай молча. Сообщи человеку и предложи, что исправить.
