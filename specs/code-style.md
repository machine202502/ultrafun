# Стиль кода

Конкретные правила. Обоснование — в [principles.md](principles.md).

## Комментарии

- Не пишем. Ни строчных, ни блочных, ни docstring, ни TODO.
- Встретил комментарий в коде, который правишь, — удали его, а смысл перенеси в имя.
- TODO и «не сделано» записываются в спек фичи или сообщаются человеку.

## Имена

- Полные слова: `player_health`, не `ph`, `hp_val`, `tmp`.
- Функция называется тем, что делает: `apply_damage`, `spawn_wave`, `is_grounded`.
- Булевы — с `is_`, `has_`, `can_`.
- Одно понятие — одно имя во всём проекте. Назвали «wave» — не называй то же самое «round».
- Имя уникально настолько, чтобы grep находил нужное без шума.

## Функции

- Короткие, одна задача. Длинная функция — норм, если читается сверху вниз без прыжков.
- Мало параметров. Больше 4 — подумай, но не заводи объект-конфиг ради одной функции.
- Ранний выход вместо вложенных `if`.
- Чистые функции там, где это не усложняет код.

## Файлы и структура

- Один файл — одна тема. Файл должен помещаться в контекст целиком, ориентир — до ~300 строк.
- Группировка по фичам, а не по типам: `player/`, `weapons/`, `enemies/`, а не `models/`, `services/`, `utils/`.
- Никаких `utils`, `helpers`, `common`, `misc` — это свалки. Код живёт рядом с тем, кто его использует.
- Вложенность папок — не глубже 3 уровней.

## Данные и константы

- Числа геймплея (урон, скорость, кулдауны) — именованные константы или данные, не магические числа в логике.
- Держи константы рядом с кодом, который их использует. Общий файл констант — только для реально общих.

## Ошибки

- Падай громко и рано на невозможных состояниях.
- Не глотай исключения. Пустой `catch` запрещён.
- Не обрабатывай ошибки, которые не могут произойти.

## Зависимости

- Новая зависимость — только с согласия человека.
- Перед добавлением: можно ли решить стандартной библиотекой или тем, что уже есть?

## Чего не делать

- Абстрактные классы и интерфейсы с одной реализацией.
- DI-контейнеры, event bus, плагинные системы без явной нужды.
- Обёртки над библиотеками «чтобы потом заменить».
- Метапрограммирование, рефлексия, генерация кода в рантайме.
- Закомментированный код.
- Форматирование вручную — если в проекте есть форматтер, запускай его.
