# 12. Режим скриншотов и запечённый отражённый свет

**Статус:** готово, ждёт оценки человеком

## Зачем
Агенту нужно видеть картинку, чтобы чинить рендер без человека. Свет без отражений выглядит плоско: тени чёрные или залиты одинаковой подсветкой, цвета соседних поверхностей не влияют друг на друга.

## Поведение
- `cargo run --release -- --screenshots [папка]` (по умолчанию `target/screenshots`) грузит уровень из `tools/screenshots.ron`, для каждого режима освещения и каждого кадра ставит камеру, ждёт 3 кадра, сохраняет `<режим>__<кадр>.png` в низком разрешении и выходит. Логика игры не идёт.
- **Лайтмап:** при загрузке уровня и при смене настроек запекания каждая грань каждого бокса уровня делится на квадраты по `gi_texel_size` метров (не больше 128 на сторону), все грани укладываются в атлас шириной 2048 с полем в 1 тексель.
- Для каждого текселя считается прямой свет ламп уровня с теневым лучом, затем `gi_bounces` раз собирается отражённый свет: 64 луча по косинусному распределению, в точке попадания берётся `(прямой + отражённый с прошлого отскока) × цвет поверхности`.
- В шейдере отражённый свет из атласа × `gi_strength` × `lamp brightness` прибавляется к свету поверхности уровня. У врагов, дверей и вспышек его нет.
- В стиле освещения: `gi`, `gi_strength`, `gi_texel_size`, `gi_bounces`; ползунки в панели F3. Смена `gi`, размера текселя или числа отскоков перезапекает уровень.

## Не входит
- Кэш лайтмапа в файле, запекание в фоне.
- Запечённый прямой свет, свечение плафонов как источник отражённого света.
- Отражённый свет на динамических объектах (пробы).

## Критерии готовности
- [x] Тест: стена не пропускает прямой свет; за стеной есть отражённый.
- [x] Тест: грани в атласе не пересекаются; перевод в half float.
- [x] Скриншоты: тени окрашены отражённым светом, швов и протечек света не видно.
- [ ] Человек оценил картинку и выбрал силу отражённого света.
