# 06. Уровни из Blender и черновик «Утилизации»

**Статус:** готово

## Зачем
Уровни строятся в Blender ([decisions.md](../decisions.md)), а не правкой RON. Первый уровень — «Утилизация» ([design/levels.md](../../design/levels.md)), пока серым черновиком (blockout).

## Как устроен уровень
Два файла в `assets/levels/`:
- `<имя>.glb` — сцена из Blender: геометрия и расстановка;
- `<имя>.ron` — атмосфера и правила, которые неудобно задавать в Blender (волны, параметры станка, здоровье мишеней).

Исходник сцены — `art/levels/<имя>.blend`.

## Правила для сцены в Blender
**Геометрия — только кубы** (браши, как в Quake): куб из `Add → Mesh → Cube`, его можно двигать, поворачивать и масштабировать. Каждый такой объект — сплошная стена или пол. Цвет — `Base Color` материала. Неплоские модели пока не поддерживаются.

Имена объектов (суффиксы Blender вроде `.001` игнорируются, поэтому объект можно копировать):

| Имя | Тип | Что это |
|---|---|---|
| `player_start` | пустышка (Empty, тип Single Arrow) | Старт игрока; смотрит туда, куда указывает стрелка пустышки |
| `enemy` | пустышка | Болванка, которая есть с самого начала |
| `target` | куб | Мишень для пристрелки |
| `arena_…` | куб или пустышка | Объекты арен: не рисуются и не мешают движению сами по себе, на них ссылается RON-файл |
| любое другое | куб | Сплошная геометрия |

## RON-файл уровня
```ron
(
    model: "utilization.glb",
    atmosphere: (...),
    target_health: 3.0,
    arenas: [(
        trigger: "arena_hall_trigger",
        doors: ["arena_hall_door"],
        waves: ["arena_hall_wave_1", "arena_hall_wave_2"],
        machine: Some((
            object: "arena_hall_machine",
            spawn_point: "arena_hall_machine_spawn",
            health: 6.0,
            spawn_interval_seconds: 3.0,
            max_alive: 6,
        )),
    )],
)
```
- `trigger`, `doors`, `machine.object` — имена кубов: берутся их положение и размер.
- Каждая волна — имя пустышек: все пустышки с этим именем (включая копии `.001`) — точки появления.
- Нет объекта с указанным именем — понятная ошибка при загрузке.

## Выбор уровня
- `level` в `settings_default.ron`: `"utilization"` или `"test_room"`.
- `F2` во время игры переключает между ними.
- Изменённые `.glb` и `.ron` уровня перезагружаются на лету.

## Черновик «Утилизации»
Собирается скриптом `tools/blender/utilization_blockout.py` (сохраняет `.blend` и экспортирует `.glb`):
1. **Цех утилизации:** игрок на ленте конвейера, впереди — пресс. Спрыгнуть и выйти.
2. **Верстак** (декорация: монтажный пистолет у игрока с самого начала).
3. **Технический коридор:** трубы вдоль стен, пар — пока просто боксы; 2 одиночные Болванки.
4. **Сборочный цех — арена:** большой зал с колоннами и платформами, 2 волны и станок у дальней стены.
5. **Выход** к пневмопочте — пока просто отмеченная площадка за ареной.

## Не входит
- Неплоские модели, текстуры, освещение из Blender.
- Пневмопочта, Диспетчер, экран итогов — отдельные спеки.

## Критерии готовности
- [x] Тесты загрузчика: кубы становятся боксами с правильным положением, поворотом и размером; пустышки — точками; копии `.001` собираются вместе; отсутствующее имя — ошибка.
- [x] Тест на настоящих данных: маршрут от старта «Утилизации» (спрыгнуть с конвейера, через проём, под трубой скольжением) доходит до арены, арена запускается.
- [x] **Человек пробежал уровень** и открыл `.blend` в Blender.

## Как пересобрать уровень
Из скрипта (перезапишет `.blend` и `.glb`):
```bash
blender --background --factory-startup --python tools/blender/utilization_blockout.py
```
Вручную: открыть `art/levels/utilization.blend`, править, затем `File → Export → glTF 2.0`, формат `glTF Binary (.glb)`, путь `assets/levels/utilization.glb`. Игра подхватит файл на лету.

После ручной правки `.blend` скрипт больше не запускать — он затрёт правки.
