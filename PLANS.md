# Черновик большого пакета задач (2026-10-29)

Временный рабочий документ. Когда задача стартует — её кусок переезжает в `specs/features/`, решения — в `specs/decisions.md`; в конце файл удаляется.

## Утверждённые владельцем решения

1. Большой уровень — **«Охлаждение», горизонт −3** (вода, пар, синий свет, градирни) — контраст с оранжевой «Литейной», продолжение спуска.
2. Текстуры — **только свои, программная генерация** (лицензия чистая, единый стиль, PS1-бюджет).
3. Remote debug — **наблюдение + управление + горячая правка данных**; команды выхода из игры нет.
4. Музыка — **своя процедурная петля** (генератор, как placeholder-звуки; заменится позже).
5. Порт remote debug — **4852**.
6. Вода в «Охлаждении» — **декоративная** (урона нет; шипящий пар остаётся hazard-зоной).
7. Атласы персонажей — **игрок + Болванка + Сварщик + Инспектор + Погрузчик** (утверждено).
8. «Охлаждение» — **заметно больше «Литейной»: 22–25 комнат**.
9. Графика — **в духе ULTRAKILL** (см. стиль-гайд в T3a и `inspiration/08-дизайн.md`).
10. **Меню и шрифты** в духе ULTRAKILL — задача T6: выбор уровня плитками со скриншотами.
11. **Декор обязателен:** лоу-поли камни, статуи, столбы/колонны, мусор, неровные поверхности — уровни не «чистая коробка», а живые пространства.
12. **Свет у каждой комнаты свой** (где-то тусклее, где-то ярко), включая «коридорные моменты» — атмосферные проходы без боя.
13. **Типология комнат:** не все комнаты наполнены активностями — часть просто проходится мимо (транзит), часть — боевые, часть — вижнетки-начинка.
14. **Существующие уровни не трогаем.** Владельца «Утилизация» и «Литейная» не устраивают, но править их сейчас не нужно: «Охлаждение» — пилот, по которому выявляем **общую модель построения уровней** (типы комнат, плотность декора, свет, текстуры).

## Порядок выполнения

**T5 → T1 → T2 → T3a → T3b → T6 → T4 → T3c**

Сначала доверенная база (T5), потом устранение системного бага геометрии (T1), потом инструменты отладки (T2 — к возвращению владельца), затем контентный пайплайн (T3a/T3b), меню (T6 — работает на существующих уровнях, плитки перегенерируются для новых), персонажи (T4) и в конце самый большой уровень (T3c), который использует всё предыдущее.

## T1. Правила построения уровней + валидатор геометрии

**Проблема:** стены-кубы пересекаются или лежат грань-в-грань → на экране текстуры мерцают и «прыгают» друг на друга (z-fighting).

**Решение:**

1. **Правила строительства** (обновить `docs/blender-levels.md` + спек уровней):
   - несущие поверхности стыкуются встык, грани в одной плоскости не перекрываются;
   - декор либо утоплен в несущую поверхность, либо отступает от неё ≥ 2 см;
   - привязка к сетке 0,5 м и стандартные толщины (стена/пол) — меньше ошибок в принципе.
2. **Валидатор в `level_loader`** (чистая математика по боксам, без Blender):
   - ошибка, если у двух боксов грани лежат в одной плоскости (допуск ~1 мм) и их проекции перекрываются — это ровно тот случай, который мерцает;
   - бокс целиком внутри другого — допустимо (утопленный декор); пересечение объёмов без общих плоскостей — допустимо;
   - отчёт: имена объектов, координаты, в чём конфликт.
3. **Запуск:** валидация включается флагом в RON уровня; включаем её только у новых уровней («Охлаждение»). **Существующие уровни не трогаем и не валидируем** — они остаются как есть. Плюс `cargo run -- --validate-level <имя>` для проверки без окна.
4. Новые уровни строятся по правилам с первого куба — чинить нечего.

**Критерий:** валидатор зелёный на «Охлаждении»; на «Утилизации» и «Литейной» поведение не изменилось.

## T2. Remote debug: агент подключается к сессии игрока

**Цель:** у владельца своя игра, у агента своя (запускается отдельно как обычно). Игра владельца запускается с флагом `--remote-debug`; агент подключается по localhost, делает скриншоты, читает позицию и луч камеры, двигает виртуальный указатель, управляет камерой и клавишами, правит данные на лету. Выключить игру агент не может.

**Решение:**

- **Транспорт:** TCP `127.0.0.1:4852`, сервер включается только флагом. Обмен строками RON (`ron`+`serde` уже в зависимостях, новых не нужно), скриншот — PNG (`image` уже есть).
- **Команды первого среза:**
  - `state` → уровень, позиция, yaw/pitch, здоровье, время, фаза арены;
  - `look_ray` → позиция глаз + направление (агент кидает луч и находит сломанную текстуру);
  - `screenshot [path]` → PNG с места камеры владельца;
  - `press <action>` / `look_delta(dx,dy)` — управление;
  - `pointer(x,y)` — виртуальный указатель (рисуется в HUD, чтобы владелец видел руку агента);
  - `reload` — перезагрузить изменённые RON-данные; `set_level <имя>` — сменить уровень.
- **Ввод:** действия агента сливаются с вводом игрока; при конфликте приоритет у игрока.
- **Однопоточность:** сервер опрашивается в кадре неблокирующе, одно соединение.
- **Клиент:** `examples/remote_probe.rs` — агент дёргает его через Bash (`cargo run --example remote_probe -- state`).
- **Безопасность:** только localhost, только с флага, whitelist команд, никаких команд выхода и записи файлов вне папки скриншотов.

**Критерий:** агент подключается к игре владельца, снимает скриншот с его камеры, называет координаты точки, куда смотрит владелец; правка `lighting.ron` подхватывается без рестарта.

## T3. Большой уровень «Охлаждение» (горизонт −3)

Разбит на пайплайн: текстуры → декоративные модели → сам уровень.

### T3a. Текстуры в рендере

- **Стиль-гайд по ULTRAKILL** (правило «похожесть — цель» из `design/vision.md`, конспект `inspiration/08-дизайн.md`): нарочито простая PSX-основа — низкополигональность, текстуры без фильтрации, запечённая по краям грязь и затемнение (вместо настоящего AO); поверх — насыщенный цветной свет и палитра зоны; детали не должны ломать читаемость силуэтов (сообщество ULTRAKILL критикует «обогащение» картинки деталями — держим лаконично).
- **Генератор атласов** (Rust, `image` уже в зависимостях): темы — «охлаждение» (кафель, конденсат, ржавчина, решётки), «промышленность» (бетон, металл, предупреждающие полосы), «лаборатория» (белый кафель, разметка), «камень/подземелье» (кирпич, кладка). Тайлы 32–128 px, атласы 256×256, nearest-фильтрация, запечённая грязь по краям тайла.
- **Рендер:** атлас-текстура в `scene_pass`, материал назначается в RON уровня по имени объекта, свет умножается на текстуру, лайтмап не трогаем. UV боксов — масштаб тайла по размеру грани.
- **Свет по комнатам:** у каждой комнаты своя схема (тусклый коридор, яркий зал, цветной акцент), задаётся лампами уровня; «коридорные моменты» — намеренно тёмные тесные проходы для контраста темпа.

### T3b. Декоративные лоу-поли модели

Цель: уровень — не «чистая коробка». Лейтмотив декора: **завод болванок, который 41 год работает без людей** — каждый предмет объясним этим миром, а не «поставили, чтобы было красиво».

- **Загрузчик:** glTF-меши как неколлизионный декор (префикс `deco_`), текстура из атласа. Неровные поверхности — визуальные накладки поверх плоских коллизий, физика остаётся честной коробкой.

**Декор укладывается в четыре слоя:**

1. **База (масштаб помещения):** колонны и пилястры, балки и фермы под потолком, крупные трубы и венткороба, кабельные пучки вдоль стен, потолочные решётки. Задаёт масштаб и «неквадратность» силуэта комнаты.
2. **Крупные формы (мебель и оборудование):** стеллажи, поддоны, ящики (целые и смятые), бочки, застывшие робо-тележки, контейнеры с **заготовками болванок** (недособранные корпуса, руки, головы в укладке), станки-короба, шкафы с инструментом.
3. **Мелочь (мусор и следы):** детали болванок на полу, обломки, инструменты, щебень, тёмные плоскости-лужи, декали-подтёки ржавчины под трубами, потёртости на полу, трафаретные номера цехов и стрелки, плакаты «по технике безопасности», предупреждающие полосы.
4. **Фирменные редкости (1–2 на уровень, сюрприз и юмор):** настенные часы, застрявшие 41 год назад; выцветший баннер «дней без травматизма: 14965»; постамент с болванкой и мемориальной доской «лучший сотрудник»; куст мха, выросший из лужи. Не плодить — rarity и делает их моментом.

**Специфика «Охлаждения»:** конденсат и наледь на трубах, сосульки с потолка, мох и плесень по углам, затопленные ямы с декоративной водой, рёбра градирен, вентиляторы в решётках, ржавые сталактиты протечек.

**Правила против солянки:**
- предмет объясним миром (автоматизация без людей, вода и ржавчина);
- материалы — только из атласов уровня, никакого отдельного стиля у декора;
- на комнатную сцену: 1–2 предмета базы + 2–3 крупных формы + горсть мелочи; фирменные — не чаще раза на уровень;
- массовые предметы повторяются сериями (стеллаж ×10 — цельно и дёшево), уникальные — только акценты.

- **Генератор моделей** Blender-скриптом (`tools/blender/decor_kit.py`), параметрический: все перечисленные семейства. Воспроизводимо скриптом и наше по лицензии.
- **Плотность декора — часть модели уровня:** у транзитных комнат декор и свет несут атмосферу, у боевых — не мешает читаемости.

### T3c. Уровень и музыка

**Это пилот: главный результат — не сам уровень, а общая модель построения уровней, выведенная по нему.**

- **Дизайн-план** по образцу `design/foundry.md`: **22–25 комнат** в три акта с типологией: транзитные (просто проходишь, атмосфера и декор), боевые (арены и стычки), вижнетки (секреты, виды, «коридорные моменты»). Вертикальность (градирни, платформы, мосты), декоративная вода и шипящий пар, 2–3 арены, контрольные точки, использование всех механик (расплав-зоны, плиты, ленты, прессы, пневмопочта, ключи, переключатели).
- **Blockout** скриптом по плану; валидатор T1 гоняется на каждом шаге.
- **По итогам уровня** — зафиксировать **общую модель** в `design/levels.md`: типы комнат и их доля, плотность и правила декора, свет по комнатам, назначение текстур, ритм «транзит → бой». Следующие уровни строятся по этой модели.
- **Музыка:** генератор амбиент-петли — спокойный слой (гул, капель, шипение пара) и боевой слой для арен; слои/кроссфейды через kira.

**Критерий:** уровень проходится с отчётом, валидатор зелёный, скриншоты по всем режимам освещения разнообразны, музыка переключается на аренах; модель уровня записана в `design/levels.md`.

## T6. Меню и шрифты в духе ULTRAKILL

**Цель:** главный экран и выбор уровней выглядят как «машинный терминал» ULTRAKILL: капслок, контраст, крупная типографика; уровни — **плитками со скриншотами**, клик — зайти.

**Решение:**

- **Шрифты:** в ULTRAKILL везде [VCR OSD Mono](https://www.dafont.com/vcr-osd-mono.font) — бесплатна для коммерческого использования, но только латиница. Берём пару: **PT Mono или Russo One** (OFL, есть кириллица — обязательна с первого дня) как основной + VCR OSD Mono для латинских акцентов (ранги, заголовки). TTF лежат в `assets/fonts/`, запись в `assets/CREDITS.md`.
- **Выбор уровня:** сетка плиток; на плитке — скриншот уровня (переиспользуем готовый режим скриншотов: `tools/screenshots.ron` + `--screenshots`), название, горизонт; клик — загрузка. Скриншоты плиток генерируются командой, для новых уровней — перегенерация.
- **Подача:** капслок-заголовки («HORIZON −3: COOLING»), вводная карточка уровня как титры слоёв в ULTRAKILL, чёрный фон с редкими акцентами палитры уровня.
- Расширяется существующий `src/menu.rs`; кнопка «УРОВНИ»/сетка в главном меню.

**Критерий:** из главного меню видна сетка уровней со скриншотами; вход в уровень одним кликом; русский текст отображается тем же шрифтом.

## Уровни через Blender — ограничение ли это

Короткий ответ: **на этом масштабе — нет, а правки вносить просто**.

- **Размер.** Геометрия — кубы, коллизии «капсула против бокса» дешёвые: «Литейная» (516 боксов, 15 комнат) после префильтра AABB стоит 0,32 мс на шаг логики, ~300 fps. Рост линейный по боксам: 22–25 комнат — без проблем.
- **Изменения.** Уровень — это данные (`.glb` + `.ron`), не код: правка подхватывается перезагрузкой на лету, без компиляции. Числа (волны, урон, двери, триггеры) — в RON-файле рядом.
- **Настоящее ограничение** — только прямые грани в коллизиях: нет цилиндров и склонов. Визуально закрывается декоративными мешами T3b (круглые трубы, градирни); если игрово понадобится настоящий цилиндр — добавляется отдельным типом объекта (parry3d умеет), расширяемо.
- **Правило правок:** blockout-скрипт остаётся источником базовой геометрии; ручные правки в `.blend` — поверх финальной генерации (повторная генерация их перезапишет — помнить). Валидатор T1 страхует любые правки.

Не блокируют старт; по умолчанию приняты мои предложения:

3. Основной шрифт из пары PT Mono / Russo One — выберу по образцу экрана, покажу скриншотом (по умолчанию Russo One для заголовков, PT Mono для текста).
