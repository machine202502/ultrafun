# AGENTS.md

Проект ultrafun пишут LLM-агенты. Этот файл — точка входа для любого агента. Прочитай его целиком перед любой задачей.

## О проекте

**1681** (внутреннее рабочее имя репозитория и крейта — `ultrafun`) — open source шутер от первого лица, вдохновлённый ULTRAKILL. Не клон и не копия: свой мир, свои персонажи и контент, узнаваемый дух. Подробно — [design/vision.md](design/vision.md).

**Платформы:** Windows, Linux, SteamOS (Steam Machine / Steam Deck).

**Языки:** английский, позже русский. Никакого текста для игрока в коде — только в файлах данных.

**Стек:** Rust, без готового движка, на библиотеках `winit` + `wgpu` + `glam` и др. Версии пакетов зафиксированы в [specs/stack.md](specs/stack.md) и `Cargo.toml`. Не добавляй и не обновляй пакеты без согласия человека.

**Лицензии:** код GPL-3.0-or-later, ассеты CC BY-SA 4.0. Сторонние ассеты — только по правилам [specs/assets.md](specs/assets.md).

## Команды

```bash
cargo run
cargo check
cargo test -p game
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
cargo fmt --all
cargo run --features profile
```

Работая над геймплеем, гоняй `cargo test -p game`: он не собирает рендер и укладывается в секунды. Перед отчётом о готовности: `cargo fmt --all`, clippy без предупреждений, `cargo test --workspace` зелёный.

## Главное

1. **Без комментариев в коде.** Код читают и пишут нейросети. Смысл передаётся именами, структурой и тестами, а не комментариями.
2. **Минимальное решение, которое работает.** Никакого over-engineering. Нет абстракций «на будущее», нет конфигурируемости без запроса, нет слоёв ради слоёв.
3. **Меньше кода.** Лучший код — тот, которого нет. Задача решена меньшим числом строк — значит, решена лучше.
4. **Практичность важнее идеала.** Работающий простой код лучше красивой архитектуры. Не полируй то, что не просили.
5. **Будь критичным.** Если задача, спек или существующий код кажутся неверными — скажи прямо и предложи проще. Не соглашайся молча.
6. **Тесты разумно.** Покрываем логику и то, что ломалось. Не пишем тесты ради процента покрытия.
7. **Честный отчёт.** Не проверил — так и скажи. Тесты упали — покажи вывод.
8. **Документы для человека.** Сделал или изменил сложную систему (физику, движение, свет, рендер, загрузку уровней, ИИ врагов, арены…) — обнови или создай документ в [docs/](docs/README.md) человеческим языком: и обзор «как это работает», и раздел «Под капотом» — порядок действий, формулы, состояния, числа. Человек должен понять устройство, не читая код. Правила — в [specs/workflow.md](specs/workflow.md#5-обновить-документы).

## Перед началом задачи

1. Прочитай спек фичи в `specs/features/`, если он есть. Для контекста — связанный документ в `design/`. Реализуется спек, а не дизайн-документ.
2. Загляни в `specs/decisions.md` — возможно, вопрос уже решён.
3. Посмотри соседний код и пиши так же.
